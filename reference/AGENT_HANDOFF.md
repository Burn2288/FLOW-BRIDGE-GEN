# Задание разработчику

Реализовать Telegram-бот озвучки на Python по текущему пакету. Минимальный интерфейс, общее платформонезависимое ядро, будущий MAX adapter. Начать с README и этапа 1.

Обязательные правила:
- Не выдавать проектные документы и MOCK за готовый продукт.
- Не выдумывать Clodex HTTP endpoints, цены и совместимость SDK.
- Держать платежи/реальные генерации выключенными до соответствующих приёмочных проверок.
- При отсутствии контракта продолжать независимую разработку ядра и UI; описать конкретный BLOCKED для live-интеграции.
- Не просить регулярного ручного подтверждения рутинных локальных изменений. Реальные платные тесты требуют отдельного разрешения на расход.
- Финансовые операции и допуск заданий выполнять атомарно; не ограничиваться отключением кнопок.
- Не выполнять автоматически новую платную генерацию при неизвестном результате старой.
- Не добавлять публичную админку, Redis, микросервисы и Mini App без необходимости.
- Не хранить ключи/персональные тексты в исходниках и отчётах.

schema.sql — исходная модель. Перед production расширить ограничения, миграции и transaction layer; текст SQL сам по себе не реализует правила приложения. В .env.example нет готового адреса TTS: заполнение только по подтверждённой документации.

После каждого этапа: что реализовано, чем проверено, PASS/FAIL/BLOCKED, следующий конкретный шаг. Окончательная сдача — по 10_ACCEPTANCE.md и 11_IMPLEMENTATION_PLAN.md.
