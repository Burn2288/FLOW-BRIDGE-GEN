# Telegram и оплата

Официальный источник: https://core.telegram.org/bots/payments-stars
Цифровая услуга внутри Telegram: Stars, currency XTR. Не заменять это внутренней кнопкой оплаты картой.

## Покупка пакета
1. Создать payments pending с immutable order UUID, user ID, ценой XTR, количеством внутренних кредитов и тарифом.
2. Отправить invoice; payload — непрозрачный order ID, не доверенные сумма/баланс из клиента. Для Stars provider_token задаётся по действующему Bot API (обычно пустой).
3. pre_checkout_query: проверить пользователя, payload, валюту, сумму, актуальность заказа и возможность исполнения. Ответить в установленный Telegram срок (10 секунд); длительные вызовы провайдера здесь запрещены.
4. Зачислять исключительно на successful_payment, не по нажатию кнопки и не по pre_checkout.
5. Проверить соответствие заказу, уникальный telegram_payment_charge_id. Сохранить payment + ledger + wallet в одной транзакции. Повтор события возвращает существующий результат.
6. Несовпадение полей: review, без зачисления; уведомить администратора и не терять событие.

Событие может быть повторено или прийти после сбоя. Устаревший pending order не повод терять подтверждённую оплату: проверить и обработать либо провести возврат с учётом журнала. Не отправлять пользователю повторно оплачивать уже успешный заказ.

## Поддержка и возвраты
/terms, /support, /paysupport, политика и понятные условия до покупки. Хранить charge ID для refundStarPayment; возврат выполняется отдельной управляемой операцией с идемпотентной локальной записью и сверкой результата после timeout. Не обещать, что внутренние кредиты равны деньгам или выводятся пользователем.

## Получение обновлений
Long polling, один consumer; updates сохранять/обрабатывать надёжно до продвижения offset, не терять платежи из-за подтверждения раньше DB commit. Дедупликация update_id и provider charge ID независимы. Для webhook — HTTPS и secret_token; переход на webhook не нужен для MVP.

Тестовые платежи запускать по актуальным инструкциям Telegram. Реальные покупки и возвраты проверять на контролируемом аккаунте с разрешённым бюджетом, не на клиентах.
