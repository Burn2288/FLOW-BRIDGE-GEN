# Развёртывание и обслуживание

Целевая начальная среда: Linux VPS, Python поддерживаемой версии, PostgreSQL поддерживаемой версии. Разработчик выбирает точные версии, фиксирует lockfile и проверяет совместимость. Локальная разработка Windows допустима; абсолютные C:\ пути не использовать.

## Компоненты
bot process, worker process, PostgreSQL, приватная папка data/audio. systemd либо Docker Compose — выбрать один и документировать реальные команды. Не заявлять этот пакет как готовый docker deployment: runnable исходников здесь нет.

## Порядок
1. Создать отдельного системного пользователя и каталоги с минимальными правами.
2. Установить зависимости из lockfile, настроить .env по шаблону без включённых платных операций.
3. Создать отдельного DB пользователя, применить миграции в staging. DDL schema.sql — стартовая основа, не изменяет существующие схемы автоматически.
4. Выполнить интеграционные тесты и восстановление backup в отдельную БД.
5. Запустить MOCK, пройти UI без реального пополнения/списания.
6. Подключить подтверждённый Clodex-контракт, выполнить ограниченный авторизованный live тест.
7. Проверить доставку, цену и деньги. Затем ограниченный пилот; публичные продажи только после приёмки.

## Конфигурация
Флаги PAYMENTS_ENABLED и GENERATION_ENABLED независимы. При MOCK оба реальных финансовых действия запрещены на уровне application service, не только UI. Rate limits и budgets применяются в ядре. Admin IDs — числовой allowlist с платформой.

## Наблюдение
Метрики: длина очереди, oldest queued age, uncertain count, provider errors, delivery failures, available/reserved totals, дневной расход и прогноз зарезервированного provider cost, диск, backup age. Alert администратору: uncertain, расход достиг лимита, несходящийся ledger, длительный простой, нехватка диска. Сообщения пользователям/админу включать только после настройки адресата владельцем.

## Backup/restore
Ежедневная зашифрованная копия БД вне VPS; ключ отдельно. Результаты можно не копировать при раскрытой краткой политике хранения. Регулярный restore в отдельную среду, без запуска бота с production токеном. Перед миграцией backup; откат кода не заменяет откат схемы. После восстановления отправленные платные операции сверить с провайдером, не переисполнять автоматически.

## Инциденты
Утечка токена: остановить соответствующий процесс, отозвать/сменить секрет, проверить расходы и доступ. Ошибка биллинга: выключить продажи и новые генерации, сохранить delivery/read history, сверить ledger. Сбой провайдера: circuit breaker, не запускать бесконечные платные retries. Потеря сети: ограниченные повторы безопасных операций.
