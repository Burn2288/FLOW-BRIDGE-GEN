# План разработки

Этап 1. Ядро: миграции, identities, wallets/ledger, quotes, jobs. Выход: A02–A04, A07, A14 проходят на PostgreSQL.
Этап 2. Telegram UI и MOCK: 4 кнопки, выбор голосов, quote, история, доставка. Выход: A01 в MOCK, A08, A13, A22.
Этап 3. Worker: leases, uncertain, проверка аудио, cleanup, рестарты. Выход: A09–A12, A15, A21.
Этап 4. Clodex: получить контракт, адаптер, короткий live тест с разрешением. Без API можно завершать предыдущие этапы. Выход: A19, подтверждённый capability JSON и cost report.
Этап 5. Stars: invoice, pre-checkout, successful payment, refund, поддержка. Выход: A05, A06, A20.
Этап 6. Пилот: дневной budget, мониторинг, backup/restore, один контролируемый пользователь. Выход: A16–A18, все обязательные тесты зелёные.
Этап 7. MAX: только после стабильного Telegram MVP, по 08_MAX.md; не блокирует Telegram.

## Сдаваемые материалы разработчика
Исходники и lockfile; миграции; .env.example без ключей; инструкции реального запуска/остановки/backup/restore; тесты; capability matrix; sanitized LIVE evidence; фактическая себестоимость; список BLOCKED; архив и SHA-256. Не писать «всё работает» без перечисления проверенного окружения и исключений.

Не включать дополнительные продукты ElevenLabs в первый релиз ради количества кнопок. Добавлять по одному, сохраняя общие jobs/ledger и ограничение расходов.
