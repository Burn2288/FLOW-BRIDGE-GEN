# Подключение MAX

Общее ядро сохраняется: кошелёк, очередь, тарифы, provider adapter, файлы. Заменяется транспорт: события, кнопки, сообщения, загрузка/доставка медиа, аутентификация платформы. Платежи подключаются отдельно после проверки возможностей и условий MAX; способ оплаты в этом пакете НЕ подтверждён.

## Что проверено по публичной документации 03.11.2026
POST /uploads позволяет получить URL для загрузки медиа; audio поддерживается. Загруженный токен используется для вложения при POST /messages. Официальные страницы на дату проверки указывают platform-api2.max.ru и заголовок Authorization; перед реализацией перепроверить текущую версию и TLS-требования. TLS verification не отключать.

## План
1. Убедиться, что владелец может создать бота, получить токен и использовать необходимые функции платформы.
2. Получить /start-аналог, событие текста, callback, ошибки и механизм получения обновлений из актуального контракта.
3. Реализовать MaxTransport с теми же application use cases.
4. Реализовать двухэтапную отправку аудио; отдельно хранить MAX attachment token, не путать с Telegram file_id.
5. Проверить лимиты размера/длительности, cooldown и доступность результата после перезапуска.
6. Платежи включать только после отдельного приёмочного теста.

## Личности и баланс
По умолчанию MAX создаёт отдельного пользователя. Объединение только по одноразовому случайному коду, подтверждённому в обеих авторизованных сессиях, с TTL и ограничением попыток; не объединять по имени/телефону без доказательства владения. MVP связывание отключено.
До проверки ограничений платформ и платёжных условий балансы Telegram и MAX изолированы; не обещать перенос оплаченных Stars-кредитов между платформами.

## Критерий переносимости
Добавление MaxTransport не меняет код генерации и ledger. Тесты ядра запускаются без Telegram SDK; одинаковые нормализованные действия дают одинаковые задания. Отдельно проверяются особенности оплаты, файлов и доставки MAX.
