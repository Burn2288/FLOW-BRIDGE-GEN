# CLODEX API — технический аудит (2026-11-03)

## Область аудита
Цель — спроектировать интеграцию CLODEX (`https://clodex.xyz`) как поставщика ИИ-функций для Telegram-бота с озвучкой ElevenLabs, оплатой, очередями генерации и учётом списаний. Это НЕ аудит одноимённого GitHub-проекта clodex и НЕ документация clidex.dev.

### Важное предупреждение
Единого подтверждённого описания **всех маршрутов CLODEX** сейчас нет. Не подставляйте маршруты напрямую из `api.elevenlabs.io` или `api.openai.com` без тестов. Не заявляйте полную поддержку ElevenLabs на основе одного названия модели в каталоге.

## Авторизация и секреты
- Вероятный способ авторизации для OpenAI-совместимых путей — `Authorization: Bearer <CLODEX_API_KEY>`, но это следует **проверить** по документации или безопасному запросу.
- Оригинальный ElevenLabs использует `xi-api-key`, однако нельзя предполагать, что CLODEX принимает этот заголовок.
- Все ключи хранятся **только на сервере**; токен Telegram и ключ CLODEX никогда не выдаются клиенту.
- Не логировать ключи, URL со секретами, аудиофайлы/персональные тексты без основания, заголовки авторизации.

## Экономика / риск
- Модель оплаты и цены из сторонних каталогов могут быть устаревшими или несопоставимыми с реальными счётами. Дату, валюту, единицы тарификации и регион нужно подтверждать у CLODEX.
- На этапе интеграции: лимит расходов на тест, ручное разрешение одного платного запроса, учёт фактического списания до и после.
- Для TTS отдельно определить: за символы, за токены, за секунды, за вызов или смешанная тарификация.
- Не привязывать внутренний биллинг Telegram-бота к оценке стоимости без фактической метрики.

## Критические неизвестные (запросить у CLODEX)
- Полный набор API endpoints и OpenAPI/Swagger/Postman collection.
- Реально поддерживаемые ElevenLabs продукты, модели, голоса, форматы, потоки, длительные задачи.
- Нужный базовый URL и заголовок авторизации для каждого семейства API.
- Код ответа и тело при ошибках 401/403/404/422/429/5xx.
- Ограничения RPS, concurrency, длины текста, размеров загрузок и времени ожидания.
- Точные правила списания, возврата средств при ошибках и повторе запроса.
- Возможность idempotency-key, cancellation, usage endpoints.
- Правила хранения/удаления пользовательского аудио и соответствие условиям провайдеров.
