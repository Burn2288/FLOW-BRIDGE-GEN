# Приёмочные проверки

Формат результата: PASS / FAIL / BLOCKED, версия кода, время, окружение MOCK/LIVE, очищенное доказательство. MOCK не подтверждает API и стоимость.

| ID | Проверка | Условие PASS |
|---|---|---|
| A01 | Обычная озвучка | После подтверждения одна работа, один MP3, одно списание |
| A02 | Двойной клик | 20 параллельных подтверждений одного quote дают один job и reserve |
| A03 | Недостаток средств | Нет job/provider call/отрицательного баланса |
| A04 | Два разных quote одновременно | Правило одной активной работы и баланс соблюдены |
| A05 | Повтор successful_payment | Один charge ID зачисляется один раз при параллельной обработке |
| A06 | Подмена оплаты | Чужой user, payload, сумма/валюта не зачисляются |
| A07 | Чужая работа | Другой user не получает текст, файл и метаданные |
| A08 | Устаревшие кнопки | Нет повторного POST или списания; понятный ответ |
| A09 | Отказ до генерации | Резерв возвращён один раз |
| A10 | Timeout после отправки | uncertain, нет автоматического повторного платного POST |
| A11 | Авария dispatching | После рестарта нет безусловного переисполнения |
| A12 | Авария после записи файла | Результат восстанавливается/сверяется без новой генерации |
| A13 | Ошибка отправки Telegram | Повтор доставки не меняет стоимость и provider calls |
| A14 | Capture против release | При гонке происходит только одно завершение |
| A15 | Истечение хранения | Файл удалён, чужие/активные файлы не затронуты |
| A16 | Дневной budget | Одновременные worker не превышают внутренний предел допуска |
| A17 | Логи/архив | Нет токенов, auth headers и приватных текстов |
| A18 | Restore | Восстановлены баланс/платежи/работы; нет повторного исполнения |
| A19 | Real Clodex TTS | Проверенные контракт, аудио, request ID и фактическая цена |
| A20 | Refund | Один возврат, согласованные payment/ledger, timeout безопасен |
| A21 | Провайдерный файл | Неверный MIME, слишком большой ответ, SSRF redirect блокируются |
| A22 | MOCK | Не создаёт реальные платежи и не расходует клиентский баланс |
| A23 | MAX | Текст/callback/аудио работают через отдельный adapter; оплата отдельно |

Деньги, race conditions и job claiming тестировать с реальным PostgreSQL в изолированной среде, а не только in-memory mock. Негативные сетевые сценарии имитировать локальным HTTP stub, не устраивать нагрузочные атаки на провайдера. Для LIVE явно записать разрешённый бюджет; прекратить тест при его достижении.
