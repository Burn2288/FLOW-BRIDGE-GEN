# Минимальная защита

## Доступ
На каждой операции проверять internal user ID и владельца ресурса в запросе к БД. Случайный UUID не заменяет проверку доступа. Callback содержит только короткий ID действия/quote; цену и владельца брать из БД. Все SQL параметризованы. Входной текст не исполняется как код/команда и не интерполируется в shell.
Административные команды — allowlist числовых ID платформы + audit. Username не даёт прав. Ручное изменение баланса — только ledger-компенсация с причиной.

## Секреты
.env вне git с правами 0600 либо менеджер секретов. Не печатать токены, auth headers и URL с секретами. Маскировать ошибки HTTP-клиента. Отдельные ключи test/prod, ротация при утечке. Сервисный пользователь ОС без root; БД не доступна из интернета.

## Файлы/сеть
MVP не принимает произвольные URL и пользовательские файлы. Provider download URLs проверяются: HTTPS, разрешённые хосты из официального контракта, запрет loopback/private/link-local и проверка всех redirect/DNS переходов. Только ограниченная загрузка с тайм-аутом и пределом bytes. Не использовать shell=True. Имена UUID, не пользовательский filename. Хранилище без публичной раздачи; доступ через проверенную операцию бота.
При будущих загрузках — проверка фактического формата, размера, длительности, безопасная обработка декодером в изоляции, запрет архивов/исполняемых файлов.
TLS-проверку не отключать ни для Clodex, ни для MAX. Не принимать сертификаты из случайных источников.

## Лимиты
Предел длины, частоты, активных задач, provider concurrency, суточного бюджета. При исчерпании бюджета не принимать платный резерв. У budget counters отдельная атомарная блокировка; локальный semaphore не защищает несколько worker. Дубли событий/кнопок не увеличивают списания.

## Данные
Предлагается хранить тексты и аудио 7 дней после завершения, затем удалить содержимое, оставить минимальные метаданные истории. Секретные тексты не писать в application logs. Учётные документы/платежные записи хранятся по принятой политике и применимым требованиям; не удалять их автоматически с аудио. Сроки резервных копий и удаления раскрыть в политике. Политика должна назвать провайдера обработки и передачу данных Telegram/MAX. Удаление у нас не означает удаления у внешнего сервиса.

## Эксплуатация
Фиксация зависимостей lockfile, миграции, резервные копии, проверка восстановления, доступ по SSH-ключам, закрытые порты, автоматический перезапуск. Обновления зависимостей проверять в staging. Никаких реальных ключей/персональных данных в audit ZIP.
