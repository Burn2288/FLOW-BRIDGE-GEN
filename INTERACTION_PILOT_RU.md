# DarkFlow Gen — взаимодействие с моделями

Обновление для версии от 5 ноября и её обновлений каталога. Распакуйте поверх
рабочей папки. Сохраните существующий .env и том PostgreSQL.

1. Добавьте в .env строку `CLODEX_INTERACTION_MODE=mock`.
2. Выполните `docker compose up -d --build bot`. Compose применит новую миграцию.
3. Откройте «Агрегаторы → CLODEX → Модели» и карточку любой модели. Для
   проверки диалога отправьте текст, затем файл .txt в UTF-8 до 24 КБ. Для
   проверки изображения нажмите «Создать изображение» и отправьте промпт.
   В mock бот вернёт тестовый текст или сохранит одноцветное PNG в «Моих работах». Платных вызовов нет.
4. Команда /menu завершает сессию. Подключение другой модели начинает новый диалог.

Диалог хранит последние три пары реплик в БД, до 2000 символов на реплику.
Длинные ответы отправляются файлом answer.txt. Изображения открываются через «Мои работы».
PDF, фото на входе, видео и произвольные вложения пока не поддерживаются.

## Реальный пилот

По умолчанию слой выключен. Адаптер реализует Chat Completions и Images
Generations с PNG/JPEG в base64. Формат ответа проверен только на подставных
ответах. URL из ответа не скачиваются. Текстовые запросы ограничены 512 выходными
токенами на уровне тела запроса, если CLODEX соблюдает параметр max_tokens.

До включения live подтвердите контракт для точного ID модели и настройте
денежный лимит на стороне CLODEX. Локальный лимит считает попытки, а не рубли.
Для включения нужны приватный доступ, ключ CLODEX, свежий каталог по ключу,
выключенные платежи, CLODEX_INTERACTION_MODE=live,
CLODEX_INTERACTION_PAIRS со списком
пар операция:ID через запятую. Доступные операции — chat и images.generate.
Требуется соответствующий протокол в метаданных модели либо явная
привязка пилота, описанная ниже. Попытки для операций с лимитом считаются накопительно. Списаний с кошелька пользователя нет.
Повтор Telegram-обновления не отправляет второй запрос. Если доставка
результата в Telegram прервётся, автоматического повторного запуска не будет.

## Nano Banana 2 через CLODEX

Установите обновление поверх проекта с исправленным меню. В существующем
`.env` задайте параметры пилота. Если список пар уже настроен, добавьте новую
пару через запятую. Генерация изображений Nano Banana 2 не расходует локальный лимит попыток.
Если разрешены другие операции, задайте для них положительный лимит.

```dotenv
CLODEX_INTERACTION_MODE=live
CLODEX_INTERACTION_LIMIT=0
CLODEX_INTERACTION_PAIRS=images.generate:nano-banana-2
```

Пилот использует существующий ключ CLODEX и требует `ACCESS_MODE=private`,
`PAYMENTS_ENABLED=false` и включённый каталог. В папке проекта выполните:

```console
docker compose stop bot worker
docker compose up -d --build
docker compose exec bot python -m elevenbot catalog-refresh
```

В Telegram под администратором откройте «Агрегаторы → Открыть каталог →
Генерировать изображение → nano-banana-2 → Генерировать изображение».
Отправьте описание. Каждый отправленный промпт может расходовать баланс
CLODEX. Откройте «Мои работы» или «Работы этой модели» в карточке. Файл появляется
в чате только при явном открытии, а при переходе по меню предпросмотр
удаляется. Отправленный пользователем промпт остаётся в переписке.
Изображение и его промпт хранятся семь дней. Озвучки тоже открываются
из «Моих работ». Записи старых озвучек без ID модели доступны в общем списке.

## FLUX Schnell на отдельном smoke-стенде

В локальном `.env` тестового проекта допишите `image:flux-schnell` в
`PUBLIC_CATALOGUE_MODELS` и `images.generate:flux-schnell` в
`CLODEX_INTERACTION_PAIRS`, сохраняя другие записи. Для пилота нужны
`ACCESS_MODE=private`, `CATALOGUE_ENABLED=true`, `PAYMENTS_ENABLED=false`,
`CLODEX_INTERACTION_MODE=live` и положительный `CLODEX_INTERACTION_LIMIT`.
Лимит считается по уже записанным ограничиваемым попыткам в БД стенда.
Для одного нового запроса он должен быть на единицу больше числа таких попыток.

Перед показом модели проверьте, что `GET /v1/models` возвращает `flux-schnell`
для тестового ключа, а свежий `/api/pricing` указывает `image-generation`.
Обновите каталог и пересоздайте только сервис бота:

```sh
docker compose -p flowbridge-live-smoke -f compose.yaml exec -T bot python -m elevenbot catalog-refresh
docker compose -p flowbridge-live-smoke -f compose.yaml up -d --no-deps --force-recreate bot
```

В тестовом Telegram откройте «Открыть каталог → Генерировать изображение →
flux-schnell → Генерировать изображение». Сначала проверьте, что появился
экран ввода промпта. После разрешения на один платный вызов отправьте один
промпт, затем откройте сохранённую картинку через «Мои работы». В отчёте
укажите SHA запуска, число попыток, результат первой и повторной выдачи.
Токен, ключ, ID пользователей и подписанные URL храните локально.

Модель появится в разделе, если CLODEX вернул её точный ID для вашего ключа.
В публичном прайсе у неё указана метка `openai`. Явная пара включает проверку
модели через общий `POST /v1/images/generations`. Совместимость проверена
с подставным ответом PNG. Живой запуск под вашим ключом остаётся первым
шагом приёмки. Бот ожидает PNG/JPEG в `data[0].b64_json` и не загружает
ссылки из ответа. Приватный пилот не публикует модель для обычных пользователей.
