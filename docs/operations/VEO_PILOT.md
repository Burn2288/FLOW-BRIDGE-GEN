# Veo 3.1 · пилот «Текст → видео»

Каталог проверяется по текущему тестовому ключу. Обычный режим использует
`clodex-video/veo-3.1`, Fast использует `clodex-video/veo-3.1-fast`.
В запросе одинаковые параметры оценки и создания — текст, 4 секунды,
720p и 16:9. Показывается предварительная стоимость в USD от CLODEX.
Подтверждение действует пять минут и относится к показанному режиму.

| Операция | Маршрут |
| --- | --- |
| Оценка | `POST /v1/videos/estimate`, стоимость в `data.cost_usd` |
| Создание | `POST /v1/videos`, маршрут обоих ID из метаданных моделей |
| Статус | `GET /v1/videos/{id}` |
| Скачивание | `GET /v1/videos/{id}/content` |

Источники — [каталог моделей](https://clodex.xyz/v1/models) и
[Video API CLODEX](https://clodex.xyz/docs#video). Примеры общего маршрута
`/v1/videos/generations` используют `request_id`. Для модельного маршрута
`POST /v1/videos` отдельный успешный ответ Veo пока не проверен. Нужны
успешные ответы создания и статуса для подтверждения их JSON-схем, а также
подтверждение, что скачивание возвращает MP4 напрямую. Адаптер принимает
`id` или `request_id`, ограничивает размер MP4 и останавливает скачивание при
редиректе. Подписанные ссылки в лог не попадают.

Пилот выключен по умолчанию. `CLODEX_VIDEO_PILOT=true` требует закрытый
режим `CLODEX_INTERACTION_MODE=live` и положительный общий лимит. Включайте
реальные вызовы только в отдельно согласованном тестовом прогоне.
Бот запоминает подтверждение до отправки запроса. Если ответ создания
потерян, повторного POST нет. Если ID получен, бот продолжает проверять
его после перезапуска. Готовый MP4 сохраняется в PostgreSQL до отправки
и открывается в «Моих работах» семь дней.

Для проверки без платных генераций запустите `tests/test_video.py` на
отдельной PostgreSQL. Тесты подменяют HTTP-ответы CLODEX и отправку в Telegram.
