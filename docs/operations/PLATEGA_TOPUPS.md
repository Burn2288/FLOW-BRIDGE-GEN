# Platega · пополнение DarkFlow | Gen

Пополнение использует общий кошелёк и журнал проводок. Выбор суммы создаёт заказ
до сетевого обращения. Условия заказа сохраняются независимо от будущих настроек.

## Настройка

В локальном .env задайте TOPUP_MODE=live, PAYMENTS_ENABLED=true,
PAYMENT_BACKEND=platega, PLATEGA_ENABLED=true, PLATEGA_MERCHANT_ID и
PLATEGA_SECRET. Ключ выдаёт подключённый магазин Platega.

PLATEGA_RETURN_URL может иметь вид
https://t.me/DarkFlowGen_Bot?start=pay_{order_id}. Параметр {order_id}
заменяется сервером. PLATEGA_FAILED_URL также поддерживает этот параметр.
Возврат по ссылке проверяет владельца в Telegram и повторно получает статус API.

PLATEGA_PAYMENT_METHOD=2 выбирает документированный метод при создании
через POST /transaction/process. Другие методы сначала согласуйте с магазином.
Суммы передаются числами JSON с точностью до копейки.
metadata.userId берётся из серверного Telegram-события,
metadata.user_email формируется как {telegram_id}@telegram.org.

В Admin Edition откройте «Платежи и пополнение». Здесь настраиваются суммы,
порядок, доступность произвольной суммы и ограничения. Курс берётся из
«Стоимость токенов бота». При 100 токенах за 10 рублей заказ на 100 рублей
фиксирует 1000 токенов. Результат пересчёта округляется вниз до целого токена.
После создания заказа сумма, токены и снимок курса неизменны.

Стартовые варианты — 50, 100 и 200 рублей, ограничения — 50–100000 рублей.
Настройки хранятся в PostgreSQL и применяются сразу.

## HTTPS callback

Зарегистрируйте в Platega URL
https://YOUR_DOMAIN/payments/platega/callback.
Домен должен иметь публичный адрес и сертификат доверенного центра.
В PLATEGA_WEBHOOK_URL сохраните этот адрес как сведения о подключении.

Запустите callback-службу из корня проекта после настройки .env.

```powershell
docker compose -p flowbridge-live-smoke -f compose.yaml -f compose.payments.yaml up -d --build platega-webhook
```

Служба слушает 127.0.0.1:8090 на хосте. На сервере настройте HTTPS reverse proxy
на этот адрес. Пример блока Caddy для выбранного домена приведён ниже.

```caddyfile
payments.example.org {
    @callback path /payments/platega/callback
    reverse_proxy @callback 127.0.0.1:8090
    respond 404
}
```

Секретные заголовки и тела запросов не включайте в access log reverse proxy.
Служба проверяет X-MerchantId и X-Secret, затем получает каноническую транзакцию
через авторизованный GET /transaction/{id}. Проверяются магазин, UUID,
payload, сумма, валюта и привязка к заказу. Возврат браузера не является оплатой.

После изменения .env пересоздайте bot и callback-службу с новой конфигурацией.
Публичный webhook на локальном стенде без домена не опубликован.

## Создание и восстановление

Один заказ допускает один POST создания. Состояние creating фиксируется
до отправки. Повторное нажатие открывает состояние того же заказа.
Если ответ потерян, создание не повторяется.

Для поиска потерянного ID используется документированный экспорт
POST /transaction/export/json за период заказа. Сопоставляются точный payload
и recordId, затем выполняется обычный GET транзакции. Экспорт не создаёт платежи.
Документация Platega противоречиво описывает результат экспорта как ссылку и как
массив. Поддержан опубликованный JSON-массив. Если магазин возвращает ссылку
или задерживает запись в экспорте, заказ остаётся unknown до сверки по callback
или с поддержкой. Автоматическое повторное создание запрещено.

Фоновый обработчик в bot сверяет выставленные заказы с паузой не менее
60 секунд на заказ. Возвраты отслеживаются и для ранее оплаченных заказов.
Закрытие меню не отменяет платёж. Поздний CONFIRMED зачисляется один раз
даже после локального истечения страницы.

Соответствие состояний провайдера и заказа приведено в таблице.

| Platega | Заказ |
| --- | --- |
| PENDING | pending, после срока expired |
| CONFIRMED | paid |
| CANCELED | cancelled |
| DISPUTED | review, новые расходы владельца закрыты |
| PARTIALLY_REFUNDED | paid с отдельной операцией возврата |
| CHARGEBACKED | refunded |
| Неизвестное создание | unknown, повтор создания закрыт |

## Возвраты и задолженность

Для частичного возврата используется накопительный refundedAmount
канонического ответа либо аутентифицированного callback после сверки
канонической транзакции. Суммы повторных событий не складываются.
Возвращаемые токены рассчитываются по снимку заказа пропорционально рублям,
с округлением вверх. Каждый прирост накопительной суммы — отдельная
неизменяемая операция topup_adjustments.

Если API сообщил PARTIALLY_REFUNDED без величины возврата и callback отсутствует,
заказ переводится в review. Требуется повтор уведомления с накопительной суммой.
Неподтверждённая сумма не используется для списания.

Доступные токены возвращённого платежа списываются проводкой topup_reversal.
Если часть уже потрачена или зарезервирована, разница записывается в wallet_debts.
Новые расходы блокируются, принятые задачи сохраняют резервы.
Следующее подтверждённое пополнение сначала погашает задолженность отдельной
проводкой topup_debt_repay. История генераций и платежей сохраняется.

Начисление topup, статус paid и очередь уведомления записываются одной
транзакцией. Уникальные ограничения защищают заказ и транзакцию от повторного
начисления. Изменения кошелька проходят через существующий ledger и его триггер.

Уведомление отправляется владельцу заказа. Оно не является навигационной
панелью. Неопределённый результат отправки уведомления фиксируется отдельно
и не приводит к повторному зачислению.

## Проверка без магазина

TOPUP_MODE=off оставляет интеграцию закрытой. TOPUP_MODE=test допускает
только разрешённого администратора с активной парольной сессией и использует
demo-кошелёк. Настоящий HTTP-клиент в test не создаёт транзакций.
В автоматических тестах подставляется транспорт Platega и отдельная PostgreSQL.

Проверяемые сценарии находятся в tests/test_topups.py и tests/test_platega_*.py.
Они проверяют штатные обработчики, webhook HTTP, гонки проверок,
неопределённое создание, повторные события, возвраты, задолженность,
изменение курса и откат транзакции при сбое до коммита.

До подключения магазина не подтверждены живое создание страницы,
проверка реквизитов магазина, доставка webhook через публичный HTTPS,
реальная оплата, банковская отмена и производственный формат экспорта.
Обсуждение в Telegram-комьюнити не является официальным разрешением Telegram.
