# OP-01 — изолированная HTTPS-проверка Mini App

Это тестовый профиль для Linux CI, а не deployment на сервер. Он использует существующую Caddy-технологию, уже описанную в документации проекта для HTTPS callback; публичный домен, DNS, действующий VPN и production не затрагиваются.

```text
Тестовый HTTP client --127.0.0.1--> Caddy :HTTP --308--> HTTPS
Тестовый HTTPS client --127.0.0.1--> Caddy :HTTPS --Unix socket 0600--> Mini App
TelegramApp + Mini App --одна тестовая schema--> disposable PostgreSQL 16
```

`deploy/test/op01/Caddyfile.template` используется только тестом. Сертификат localhost создаётся на один день во временном каталоге. Caddy слушает только loopback и принимает только `/`, `/healthz`, `/assets/*` и `/api/v1/*`; админский интерфейс Caddy выключен. При проксировании подменённые `Forwarded`, `X-Forwarded-For`, `X-Forwarded-Proto`, `X-Forwarded-Host` и `Host` удаляются или заменяются зафиксированными значениями. Это тест конфигурации, а не проверка границ доверия всех будущих внешних ingress.

Тестовый backend слушает Unix-сокет с правами 0600, а не TCP-порт. Пользователь ОС, владеющий сокетом, всё равно может обратиться к нему напрямую; изоляция не является защитой от скомпрометированного локального аккаунта. Обычная существующая `compose.miniapp.yaml` публикует backend только на loopback хоста; этот тестовый профиль её не меняет и не доказывает сетевую конфигурацию будущего сервера.

Добавлен `GET /healthz`: техническая проверка `SELECT 1` возвращает только `{"status":"ok"}` или 503 без вывода DSN и stack trace; это не проверка всей бизнес-логики. Mini App использует те же `Service`, identity и wallets, что и Telegram. Тест использует fake TelegramApp в процессе проверки, а не живого Telegram-бота. Сессия использует bearer token, а не cookie; заголовки CORS не разрешают произвольные origins. Конфигурация private-pilot взята из незавершённого композита PR #26, включающего PR #24; она не является принятой main.

Команда в изолированной Linux-среде с одноразовой PostgreSQL `op01_test` на loopback: `python -m pytest -q -s -p no:cacheprovider verification/op01/test_https.py`. Workflow устанавливает Caddy/OpenSSL и Python-зависимости, задаёт только синтетические credentials и удаляет собственную временную схему. Guard теста отклоняет другие адреса/порты/имена БД и запуск без `OP01_DISPOSABLE_POSTGRES=YES` до соединения. Этот guard относится к тесту, а не заменяет production-конфигурацию приложения.

Отзыв tester проверяется после перезапуска тестового backend с обновлённой конфигурацией; все рабочие процессы должны получить обновление отдельно. Решение D-05, внешний HTTPS, реальный домен и проверка Telegram с телефона остаются открытыми. Формальное peer review отложено; общие HTTP/access-файлы требуют согласованной границы writer/reviewer перед интеграцией.
