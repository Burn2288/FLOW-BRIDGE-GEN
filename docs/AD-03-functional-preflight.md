На одноразовой PostgreSQL 16.15 после миграций два тестовых аккаунта приняли условия. Администратор прошёл штатный парольный вход Telegram через `/admin`. Для обоих аккаунтов отдельный экземпляр HTTP-приложения принял подписанный вход Mini App и вернул собственный кошелёк с HTTP 200. Оба увидели четыре вкладки «Каталог», «Мои работы», «Баланс», «Настройки». Пункта входа в графическую админку нет.

| Области или действие | Наблюдение для администратора и обычного пользователя |
| --- | --- |
| Пользователи, задания, очередь | Экраны отсутствуют. Диагностика чужого задания по ID через графический интерфейс недоступна. |
| Провайдеры, модели, тарифы | Доступен пользовательский каталог. Административных экранов общего HTTP API нет. |
| Платежи, проводки | Личный кошелёк доступен. Административного просмотра операций других пользователей нет. |
| Отчёты, аудит | Экраны и административные маршруты отсутствуют. |
| Предпросмотр, подтверждение и откат настройки | Команда через графический интерфейс недоступна обоим аккаунтам. |

Проверена таблица зарегистрированных маршрутов aiohttp и обе сессии. Диагностические GET по десяти именам областей под `/api/v1/admin/` и POST к `settings/{preview,confirm,rollback}` под тем же префиксом вернули HTTP 404 для обоих аккаунтов. Эти адреса использованы как пробы, контракт их имён не утверждён. Отсутствие маршрутов исключило чтение админских данных через них, но не доказывает разграничение доступа к работающему экрану.

Локальный профиль: `tests/test_admin_access.py` и `tests/test_openapi_viewer.py` вместе с разовой диагностикой двух HTTP-сессий — **8 passed**. Это проверка фактического состояния базы разработки. Положительная графическая приёмка — **0 из 10**.

Для продолжения нужен SHA общего API с HTTP-ролями и административным входом AD-01, разрешённой командой с preview/confirm/rollback AD-02 и операционными и финансовыми представлениями OB-02.
