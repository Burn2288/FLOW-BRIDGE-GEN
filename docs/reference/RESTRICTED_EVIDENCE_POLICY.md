# Порядок хранения закрытых доказательств

Предложен вариант A: отдельная ветка существующего закрытого хранилища, владелец Burn2288. Доступ владельца к хранилищу подтверждён; проверка прав vankhu21 вернула отсутствие доступа. Доступ независимого аудитора не подтверждён: AUDITOR_ACCESS_BLOCKED. Закрытые свидетельства остаются локальными до организации проверяемого совместного доступа; доступ нельзя считать предоставленным по факту приватности репозитория.

Перед размещением проверить право чтения обоих разработчиков и аудитора, запретить публичные ссылки, выявить секреты и лишние персональные данные. Доступ предоставляется владельцем по минимальным правам. Изменения оформляются версионированными коммитами, удаления — с обоснованием и сохранением архивной версии; публичный указатель содержит только непрозрачный идентификатор и стабильную ссылку на конкретный разрешённый commit, без внутренней карты. Следующие пакеты получают новые ревизии и сохраняют историю. Пока такой commit и права доступа не подтверждены, ссылку на доступные аудитору доказательства не заявлять.

| Идентификатор | Категория | Доступность |
| --- | --- | --- |
| PRIVATE-REFERRALS | Закрытые evidence по рефералам | LOCAL_ONLY |
| PRIVATE-PAYMENTS | Закрытые evidence по платежам | LOCAL_ONLY |
| PRIVATE-SUPPORT | Закрытые evidence по поддержке | LOCAL_ONLY |

Публичная ветка audit-artifacts не является ограниченным хранилищем. Полная локальная история с закрытыми данными не предназначена для push в публичный репозиторий.
