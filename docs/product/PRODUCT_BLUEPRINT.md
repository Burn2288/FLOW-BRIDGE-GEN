# PRODUCT BLUEPRINT — продуктовая модель

Статус: DESIGN_DRAFT. Источник: OWNER_REQUIREMENT + BASE_DIRECTIVE. Отдельно различать согласованное направление и предложенные детали.

## Назначение

Пользователь Telegram получает доступ к AI-контенту после регистрации и принятия документов, пополняет внутренний баланс, выбирает модель подключённого AI-агрегатора и создаёт изображения, видео, озвучку текста или песни по собственному промпту. Сгенерированный оплаченный материал сохраняется в личной библиотеке для повторного скачивания/доставки без повторной платы за генерацию.

Два независимых интерфейса одного backend: 1) меню и сообщения Telegram DM; 2) графический Mini App с полным функциональным паритетом. Возможность открыть Mini App не отменяет существование чат-бота.

## Доменные сущности

- User: Telegram ID, профиль, согласие с версиями документов, статус доступа, реферальное происхождение.
- Wallet: доступный и зарезервированный баланс в минимальных денежных единицах; LedgerEntry — неизменяемый факт проводки.
- PaymentIntent: попытка пополнения у платёжного провайдера, внешний id, подтверждённые сумма/валюта, жизненный цикл, сверка.
- ReferralAttribution, ReferralReward: связь приглашённого и пригласившего, политика наград, выдача/откат.
- Provider, CredentialReference, Capability, Model, ModelVersion: агрегаторы и доступные модели, декларативные возможности и ограничения.
- PriceQuote: зафиксированная котировка с тарифом, валютой, сроком жизни, версиями правил.
- GenerationJob / Attempt: запрос пользователя, параметры, состояния, провайдерский request id, списания и ошибки.
- MediaAsset / LibraryItem: сохранённый объект с владельцем, типом, правами и указателем на безопасное хранение.
- SupportTicket: обращения из обоих клиентов.
- AuditEvent / FeatureFlag / AdminSetting: контроль административных действий.

## Пользовательские потоки

A. /start → upsert идентификаторов → показ действующих .md юридических документов → явное согласие → главный экран. При смене соглашения требуется перепринятие актуальной версии; отказ закрывает продуктовые действия, оставляя доступ к документам и поддержке.

B. Открыть студию → тип контента → модель → форма промпта и параметров → серверная котировка → проверка доступных средств → подтверждение → резерв → запуск задания → мониторинг → финальный расчёт → результат в библиотеке → доставка Telegram или открытие Mini App.

C. Личный кабинет → мой баланс → пополнить / проверить платёж / история операций; кабинет также содержит профиль и настройки (предложение).

D. Реферальная система → личная ссылка / приглашённые / статистика / начисления / условия; деньги и бонусы считаются по серверным подтверждённым событиям, а не по нажатию на ссылку.

E. Моя библиотека → Фото / Видео / Озвучка текста / Музыка → листинг по 5 элементов, строка: обрезанное начало промпта | итоговая цена, далее карточка, просмотр, скачать, повторно отправить, новая генерация с аналогичными параметрами (новая платная операция только с отдельным подтверждением).

F. Поддержка → тикет / ответ / статус; единая линия обработки независимо от UI.

## UX и визуальное направление

Telegram DM: единое изменяемое меню, минимальное количество вспомогательных сообщений, короткие понятные подписи, до 5 позиций на странице, постоянная кнопка «Назад». В Mini App: спокойный современный интерфейс, приоритет каталога и действия «Создать», явная цена до подтверждения, визуальная карточка результата, прозрачные статусы выполнения, контрастные CTA, адаптивность под мобильную ширину, поддержка Telegram theme, light/dark, состояния loading/empty/error, доступность. Точное соответствие будущему референсу — отдельный этап визуального утверждения.

## Вехи результата

P0 — реальная E2E генерация и долговечная библиотека изображений; P1 — баланс + Platega и правдивый финансовый учёт, расширение типов генерации; P2 — полный функциональный паритет Mini App, админка и самообслуживаемый каталог провайдеров; P3 — нагрузка, восстановление, коммерческий пилот. Эта группировка продуктовая, не заменяет инженерные S0–S8.

## Обязательные решения владельца перед финансовым MVP

Валюта и политика конвертации, срок хранения оплаченных материалов, правила возврата/отмены после старта генерации, тарифы по моделям, реферальный процент и база начислений, лимиты промпта, возрастные/контентные ограничения, локализация, политика хранения загруженных пользовательских файлов, текст и версия соглашений. До решения — конфигурируемые политики с консервативной безопасной деградацией.
