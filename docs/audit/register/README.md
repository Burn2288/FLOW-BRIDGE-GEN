`TEST_EVIDENCE_PASS` описывает тесты конкретного содержимого; `PEER_REVIEW_DEFERRED` означает отсутствие итогового ревью; `NOT_INTEGRATED` означает, что кандидат не вошёл в принятую main; `NOT_ACCEPTED` означает, что окончательная приёмка не проведена. Отдельные независимые вердикты приводятся вместе со ссылками на опубликованные заключения и сохраняют их ограничения. У исторических preflight/closure нет отдельного публичного кодового кандидата, поэтому `candidate_sha` равен `null`; независимый публичный источник — PR #17.

Каталог содержит неизменяемые ссылки на приватные отчёты, SHA коммита и Git blob SHA, подтверждённые через GitHub на момент снимка. Содержимое закрытых отчётов здесь не копируется. Offline-проверка сверяет наличие записи в локальном каталоге, формат URL, SHA и взаимные ссылки; она **не проверяет сетевую доступность, актуальность PR, существование удалённого объекта после снимка или личность аудитора**. CI использует только публичные файлы и не требует приватных credentials. `tested_sha` обозначает проверенное содержимое; `checkout_sha` отдельно фиксирует фактический checkout, а для синтетического merge приводится ссылка сравнения деревьев.

Запуск из корня:

```sh
python .github/check_audit_register.py
python -m unittest discover -s .github/tests -p 'test_audit_register.py'
python .github/check_docs.py
```

Действующая main ещё не содержит предложенные `MANIFEST.schema.json` и `.github/check_planning.py` из документационного кандидата IN-18; здесь эти инструменты не выдаются за принятые. Проверки не заменяют обязательные protocol/schema/archive gates. После утверждения IN-18 и принятия контракта потребуется совместить формат и историю с согласованной схемой, не переписывая прежние заключения.
