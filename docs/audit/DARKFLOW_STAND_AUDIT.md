Дата проверки — 15 ноября 2026, МСК. Аудит исходников и штатного поведения приложения. На стенде выполнены только чтение метаданных, запросы состояния БД и проверка пакетов. ### Ключевая финансовая цепочка

Отдельный тест обычного пользователя вне списка админов. Принятие условий и зачисление через локальную заглушку Platega. Один экземпляр TelegramApp, `PAYMENTS_ENABLED=true`, `TOPUP_MODE=live` для имитации live-кошелька. Вызовы платежей и генерации направлены в HTTP-заглушки. Подтверждение генерации прошло через штатный обработчик Telegram, вызов оплаты — через сервис приложения.

| Шаг | Доступно / резерв | Статус / проводки | POST генерации |
|---|---:|---|---:|
| До пополнения | 0 / 0 | 0 проводок | 0 |
| Подтверждение 100 ₽ и повторная проверка заказа | 1000 / 0 | succeeded, 1 проводка | 0 |
| Нажатие «Генерировать» | 1000 / 0 | succeeded, по-прежнему 1 проводка | 0 |

Ответ: «Тестовый запуск для этого аккаунта недоступен». Результат в библиотеке для этого запроса отсутствует, задача не принята. Проверка ожидаемого отказа — 1 passed в 4,80 с. Публичный сценарий при этом провален. Условие в [task_launch.py:32](../../src/elevenbot/task_launch.py#L32) отклоняет и включённые платежи, и обычный аккаунт. Несовместимость ряда пилотных флагов закреплена в [config.py](../../src/elevenbot/config.py#L135). Тест [test_topups.py:293](../../tests/test_topups.py#L293) подменяет конфигурацию для генерации, поэтому доказывает общий учёт баланса, но не подтверждает единый пользовательский путь.

## 3. Безопасность и эксплуатация

| Серьёзность | Наблюдение и последствия | Минимальное исправление |
|---|---|---|
| Высокая, блокер выпуска | Воспроизведённое пополнение не даёт обычному аккаунту запустить задачу при активных платежах. Средства могут быть зачислены без доступной оплаченной функции. [TaskLaunch](../../src/elevenbot/task_launch.py#L29), [тест с заменой конфига](../../tests/test_topups.py#L293). | Отдельная явная политика публичного запуска для проверенных адаптеров и допусков. Сохранить пилотную политику и транзакционный резерв. Приёмка с неизменяемым конфигом и обычным аккаунтом. |
| Высокая, условие платформы | Оплата цифровой услуги из Telegram требует отдельной проверки канала. Telegram указывает Stars для цифровых товаров и услуг в ботах и Mini Apps. [Правила Telegram](https://core.telegram.org/bots/payments-stars). | До публичного выпуска подтвердить назначение продукта и платёжный канал. Для применимого сценария внедрить Stars в общий путь пополнения и сверки. |
| Средняя, переносимость | `doctor` хеширует байты, а мигратор нормализует окончания строк. Из-за CRLF в Docker-образах сравнение может дать ложное расхождение. [doctor](../../src/elevenbot/__main__.py#L39), [migrate](../../src/elevenbot/db.py#L14). | Использовать одну функцию вычисления хеша и фиксировать LF при сборке. Переносимый override уже монтирует нормализованные SQL. |
| Средняя, эксплуатационная | На стенде есть токены Telegram и провайдеров в переменных Docker. Доступ оператора к Docker требует защиты, контейнерные env и копии нельзя публиковать. Дополнительно резервные копии содержат пользовательское состояние. [Compose](../../compose.yaml). | Ограничить Docker и файловые ACL, использовать менеджер секретов при промышленном запуске, шифровать резервные копии и периодически проверять срок хранения/восстановление. |
| Средняя, качество доказательств | Заявление о сквозной оплате требует отдельной приёмки. Автотест с двумя конфигурациями не обнаруживает блокер. Высота баннера и управление клавиатурой зависят от клиента. | Добавить критерии релиза для единого конфига и матрицу версий Android / Desktop с записью проверки. |

Контейнер бота работает как `bot`, read-only, `cap_drop=ALL`, `no-new-privileges`. PostgreSQL не публикуется наружу через Compose. Роль `elevenbot_app` может входить, без superuser/CREATEDB/CREATEROLE. Авторизация объектов применяется в сервисном слое. В public не включён RLS, поэтому новый HTTP-слой обязан вызывать те же проверки владельца и не должен выдавать доступ к БД клиенту. Для кошелька используются серверные оценки, транзакционные блокировки и проводки; неизвестный исход не должен повторять создание заявки. [Кошелёк](../../src/elevenbot/task_wallet.py) · [Диспетчер](../../src/elevenbot/task_launch.py).

В выборке последних логов есть события регистрации команд, обновления каталога и взаимодействий, а также неструктурированные строки. В отчёт попали только агрегаты, абсолютную гарантию отсутствия чувствительных данных во всех логах эта проверка не даёт. Проверенные версии: aiogram 3.31.0, aiohttp 3.14.5, asyncpg 0.32.0, httpx 0.28.1, Pillow 13.0.0, simplejpeg 1.9.0. Версии закреплены в [lockfile](../../uv.lock). uv --no-cache pip check подтвердил совместимость 28 пакетов. Это проверка требований пакетов. Покрытие актуальными CVE не подтверждено.

## 4. Mini App и веб-админка

Пригодны для повторного использования проверки владельца, кошелёк и библиотека из [core.py](../../src/elevenbot/core.py), правила и метаданные цены из [pricing.py](../../src/elevenbot/pricing.py), [task_wallet.py](../../src/elevenbot/task_wallet.py), провайдерские адаптеры и каталоги. Переиспользование этих модулей требует вызывать их с уже подтверждённым внутренним user ID и тем же режимом кошелька.

Нужно выделить API приложения из [telegram.py](../../src/elevenbot/telegram.py#L509). Задачи сейчас принимают Telegram update ID на пути подтверждения. Статусы [progress.py](../../src/elevenbot/progress.py) зависят от чата и сообщения, восстановление связано с циклом polling, а результат доставляет Telegram-адаптер. Нужны независимый идентификатор запроса, общий обработчик задач, транспорт результата и HTTP-выдача с проверкой владельца. Наблюдаемый HTTP вход — [Platega webhook](../../src/elevenbot/platega_web.py#L32), в этом Compose он выключен. Пользовательских JSON-маршрутов, входа Mini App и веб-интерфейса нет.

| Этап | Объём на одного разработчика | Зависимости и критерии |
|---|---:|---|
| Только чтение | 1–2 недели | HTTPS, авторизация initData, каталог, остатки и список работ, выдача своего файла, версии контракта и тесты отказа для чужих объектов. Суммы и работы совпадают с ботом. |
| Запуск генераций | 2–4 недели | Общая серверная политика запуска, idempotency key с владельцем, неизменяемая оценка, одна транзакция принятия и резерва, общий исполнитель с состоянием в PostgreSQL. Подтверждение и гонки между ботом и Mini App дают один POST и одно списание. Проверить рестарт, отказ и неизвестный исход. |
| Веб-админка | 2–4 недели | Общие серверные разрешения, усиленная короткая сессия для действий, аудит тарифов, курсов, допусков и рассылок. Любой прямой запрос проверяет роль и состояние сессии, выход отзывает доступ, протоколируются актор, ресурс, операция, время и безопасный diff. |

Оценки предварительные, включают интеграционные тесты и зависят от числа веб-экранов. Для входа сервер проверяет подпись сырого initData по алгоритму Telegram с серверным секретом, сравнивает подпись постоянным по времени сравнением, контролирует свежесть auth_date, обрабатывает повтор обмена, затем выдаёт короткую серверную сессию. Telegram ID берётся только из проверенных данных и связывается через существующую таблицу identities. Применяются проверка согласия, блокировки аккаунта и роли на сервере. Для веб-сессий нужны защищённые cookie или эквивалентная схема, защита мутаций и отказ при истёкшей или отозванной сессии. [Официальный алгоритм Telegram](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app).
