# Admission DB privilege boundary — disposable fixture, not production setup

This candidate intentionally leaves migration 040 and the current application code unchanged. The separate `verification/admission_test_privileges.py` procedure applies grants only to a generated `test_<uuid>` schema and generated roles in the isolated pytest server. It is not a production migration or provisioning tool. The existing `TEST_DATABASE_URL` guard is required before any cluster role/database operation; the profile must identify a dedicated disposable server, not an arbitrary forwarded endpoint.

Tests create actual distinct login roles: migration owner, read-only runtime and trusted test-only policy operator. They remove simulated overbroad table grants, revoke PUBLIC table/function access, assign schema/table/function ownership, and check runtime cannot alter policy, membership, audit, trigger/function, schema ownership or grant itself owner role. Administrative SQL in this fixture is **not** a production interface: the test callback is not non-forgeable admin authentication and the trusted operator has direct write privileges. No `SECURITY DEFINER` function is added. Bootstrap, admin identity/capability, credential custody, recovery, D-04, inherited roles, full privilege inventory, rollout and peer review remain open.

PostgreSQL `SELECT ... FOR SHARE` needs additional row-lock privileges: the existing `admission_store.require_on` cannot be used by the SELECT-only runtime role under this fixture. Granting UPDATE just to make it work would let runtime modify policy, violating least privilege. A narrowly scoped reviewed server-side mechanism or another safe serialization design is required; no route is wired and cutover remains blocked. Withholding UPDATE from runtime also does not protect against a compromised migration owner or authorized policy credential. The audit trigger does not prevent forged INSERT by an authorized operator; actor authentication and an independently protected audit destination remain design blockers.

The backup fixture populates versioned policy with multiple admins/testers and audit records, dumps a generated test schema with `--no-owner --no-acl`, restores to a generated disposable database, compares contents and explicitly reapplies the fixture ACL. This avoids claiming backup alone restores safe role grants. Test setup and cleanup create/drop cluster roles and one generated database only on the dedicated ephemeral CI service; never run on shared or production PostgreSQL.

Run `python -m pytest -q -s -p no:cacheprovider tests/test_admission_privilege_boundary.py` only under the disposable profile. Success demonstrates this isolated ACL arrangement, not production readiness, deployment privilege safety, or real admin authorization. Existing private-pilot Config remains active.
