# Private pilot across processes — test protocol

The fixture launches three independent operating-system processes: two real `TelegramApp` instances with a fake in-memory bot and one real Mini App HTTP server on loopback. Each process gets its own Config from environment, its own asyncpg pool and a distinct backend PID against the same disposable PostgreSQL database/schema. It never contacts Telegram or paid providers. All credentials and identities are synthetic; session tokens and initData are not printed.

The test observes administrator admission (not administrative login), outsider rejection before identity/wallet or financial writes; tester consent, session, own library and cross-user denial; old initData and expiry; reuse of an unexpired session across a backend restart. It then replaces A with a revoked config while B and the Mini App remain stale, replaces the Mini App, and finally replaces B. The stale window printed by the test is the elapsed time for this controlled sequence, not an upper bound on deployment propagation. There is no automatic centralized reload: each process must be restarted or otherwise supplied fresh configuration. Existing in-flight operations started before revocation have no demonstrated cancellation guarantee.

After all replacements the test checks old callbacks and the previously issued session are denied, with identity, wallets and financial row counts preserved. It tests process-unavailable behavior by stopping A. The test does not claim a race-free revocation linearization point, a live Telegram WebView, all possible callbacks/endpoints, generation execution, or an administrative API that does not exist. Process termination during an in-flight HTTP response, simultaneous revocation against an already authorized operation, and real deployment coordination are NOT_TESTED and require a separate agreed contract; no centralized access-versioning mechanism is introduced here.

Run on the existing disposable PostgreSQL fixture: `python -m pytest -q -s -p no:cacheprovider tests/test_pilot_multiprocess.py tests/test_private_pilot.py miniapp/tests/test_miniapp.py tests/test_task_wallet.py`. No production DSN, token, real user, or external AI/payment endpoint is permitted. The shared DSN guard must remain enabled.
