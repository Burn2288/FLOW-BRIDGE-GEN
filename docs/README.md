# Каталоги проекта

Одинаковые относительные пути действуют в локальных клонах и на GitHub. Git хранит каталоги через их файлы. Начальные документы находятся в `docs/`. Каталоги приложения появляются при импорте соответствующих файлов.

| Путь | Содержимое |
| --- | --- |
| [`docs/audit/`](audit/AS_IS_ARCHITECTURE.md) | Фактическая архитектура, путь изображения, результаты аудита. |
| [`docs/architecture/`](architecture/SYSTEM_OVERVIEW.md) | Целевое устройство, границы модулей, потоки, отказы и ADR. |
| [`docs/contracts/`](contracts/README.md) | Версионированные API, провайдеры, очередь, финансы, медиа и события. |
| [`docs/operations/`](operations/DEPLOYMENT.md) | Деплой Ubuntu, наблюдаемость, восстановление и инциденты. |
| [`docs/product/`](product/PRODUCT_SCOPE.md) | Объём продукта, Mini App, админка и отчётность. |
| [`docs/acceptance/`](acceptance/TEST_MATRIX.md) | Матрица, обезличенные доказательства и ограничения. |
| `docs/workplans/<логин>.md` | Личный план в соответствующей ветке. |
| `src/elevenbot/`, `tests/` | Исходный Python-пакет и тесты после импорта. |
| SQL-миграции, `reference/`, `reports/` | При импорте сохранить исходные пути и порядок миграций. Проверить актуальность старых документов, сопоставить их с новыми и избежать дублирования. |
| `.github/workflows/` | Автоматические проверки GitHub Actions. |
| `.env`, `.venv/`, `.local/` | Локальная конфигурация, окружение и рабочие данные. `.local/` используйте для тестовых медиа, сырых трасс и дампов. |

Начальный импорт должен сохранить рабочие точки запуска, имена пакетов и способы загрузки миграций. Разделение кода по модулям оформляется после аудита правилами зависимостей и отдельными вертикальными срезами.

Связанные документы добавляйте, когда есть фактический материал. Для архитектуры запланированы `MODULE_BOUNDARIES.md`, `DATA_FLOW.md`, `FAILURE_MODEL.md` и `ADR/`. Для эксплуатации — `BACKUP_RESTORE.md`, `INCIDENT_RESPONSE.md`, `RUNBOOK.md`, `MONITORING.md`. Для продукта — `MINI_APP.md`, `ADMIN_PANEL.md`, `REPORTING.md`.
